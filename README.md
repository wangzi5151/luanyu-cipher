# 乱语 LuanyuCipher

**密钥 + 原文 → 谁也看不懂的乱语。** 另一端拿着同一把密钥，一键还原原文。

一个纯原生 Android 加密工具：输入双方私下约定的几个数字或字母（密钥），再输入要保密的文字，输出一段看似杂乱的乱码文本；对方用同一把密钥即可准确还原。密钥不对、乱文被篡改一个字节，都会明确失败，绝不吐出错误的"原文"。

## 特性

| 特性 | 说明 |
|---|---|
| **高级模式：多密钥 ×10** | 最多 10 把密钥层层链式推导（Luanyu v2），顺序敏感、缺一不可 |
| 认证加密 | AES-256-GCM，密文任何一处被改动都会被检测并拒绝解密 |
| 强密钥推导 | PBKDF2-HMAC-SHA256 × 600,000 次迭代 + 16 字节随机盐（OWASP 推荐强度） |
| 同文不同密 | 同一段原文，每次加密输出都完全不同（随机盐 + 随机 IV） |
| 乱码外观 | 64 符号乱序字母表编码，输出纯 ASCII 乱文，复制粘贴过微信/QQ/短信不会被破坏 |
| 密钥空间可视化 | 实时估算"多少种组合"：基础单密钥 / 高级组合空间，不足万亿级会黄色警示 |
| 零权限 | Manifest 中**一个权限都不申请**（无 INTERNET），应用物理上无法外传数据 |
| 密钥不落盘 | 密钥只存在于内存，关闭应用即遗忘 |

## 加密原理（Luanyu v1/v2）

```
基础模式 v1（单密钥）:
  salt ← 16 字节随机数          iv ← 12 字节随机数
  dk   = PBKDF2-HMAC-SHA256(密钥, salt, 600000 次, 256 bit)
  帧头  = 'L' 'Y' 0x01 | salt                    ← 同时作为 GCM 的 AAD
  密文  = AES-256-GCM(dk, iv, AAD=帧头, UTF-8(原文))   ← 含 128 位认证标签
  输出  = 乱序字母表Base64(帧头 | iv | 密文||tag)

高级模式 v2（多密钥 1..10 把，层层链式加锁）:
  K1 = PBKDF2-HMAC-SHA256(密钥1, salt, 600000)
  Ki = PBKDF2-HMAC-SHA256(密钥i, K(i-1)‖salt, 600000)   i = 2..n
  dk = Kn
  帧头 = 'L' 'Y' 0x02 | n | salt                 ← n=密钥数, 同为 AAD

解密:
  还原字节 → 校验 magic/版本/密钥数 → PBKDF2 推导同一把 dk → GCM 验证标签 → UTF-8 还原原文
  （自动识别 v1/v2；密钥数不匹配会明确提示『由 N 把加密，你提供了 M 把』）
```

**为什么强？**

1. **原语全部是标准算法**：没有自造密码学原语。AES-GCM 是 NIST 标准的认证加密，PBKDF2 是标准密钥拉伸函数。
2. **随机盐 + 随机 IV**：同一段明文每次产生完全不同的密文。帧头（含 salt）作为 GCM 附加认证数据，攻击者改 magic、版本号、salt、IV 或密文中任何一比特，标签校验立即失败。
3. **不内嵌密钥校验位**：方案刻意不在密文里放任何"可快速验证密钥对不对"的字段。攻击者**在不知道原文哪怕一个片段的情况下，无法确认自己的密钥猜测是否正确**——所有猜测看起来同样合理。
4. **密钥空间**：

   | 密钥 | 组合数 |
   |---|---|
   | 6 位纯数字 `123456` | 100 万 |
   | 6 位小写字母 | ≈ 3 亿 |
   | 6 位混合 `aB3xY9` | ≈ **568 亿** |
   | 7 位混合 | ≈ **3.5 万亿** |
   | 7 位混合 + 符号（95 字符集） | ≈ 7×10¹³ |

   再乘上 PBKDF2 每猜一次就要算 60 万次 HMAC-SHA256 的成本，暴力破解不现实。**密钥 7 位以上即可稳超万亿量级**，App 内会实时显示当前密钥的空间大小。
5. **多密钥组合空间**（高级模式）：链式推导意味着攻击者必须**同时猜对全部密钥且顺序一致**——组合数是各把密钥空间之积：3 把混合密钥 ≈ 10³⁵ 量级，10 把更是天文数字（App 用对数计算，不会溢出）。
6. **零权限**：应用没有 `INTERNET` 权限，从系统层面就无法联网，代码没有任何通道把密钥或原文送出去。

**诚实的风险提示**：

- 安全的根基是**密钥的机密性**。请把密钥通过另外的渠道（当面说、另一个已知安全的信道）告诉对方，**不要把密钥和乱语一起发送**。
- 若密钥只有 4~5 位，即使算法再强也可被暴力穷举（App 会直接拦截少于 6 位的密钥）。
- 若攻击者已知原文的相当一部分（已知明文）且能拿到密文，可离线验证密钥猜测——所以长密钥永远更安全。
- 本项目为独立实现，未经过第三方密码学审计，适合日常隐私通信练习使用；极高价值机密请使用经过审计的成熟工具。

## 使用方法

1. 双方**提前约定**一把密钥（例如 `Xk7#9pQm`，6 位以上，数字/字母/符号混合更好），通过另一条渠道传递。
2. 发送方：选「**加密**」→ 输入密钥 → 输入原文 → 点「**加密**」→ 复制乱语发给对方。
3. 接收方：选「**解密**」→ 输入同一把密钥 → 粘贴乱语 → 点「**解密**」→ 得到原文。
4. 中间的「**交换**」按钮一键把输出换到输入框并切换模式，连续正反操作非常顺手。

**高级模式（多密钥 ×10）**：点密钥栏右侧的「多密钥 ×10」按钮，密钥框变为多行——**每行一把密钥，最多 10 行**（每把至少 4 位，空行自动忽略）。双方必须按**完全相同的顺序**输入全部密钥，否则无法解密；密钥数不匹配时会明确提示"由 N 把加密，你提供了 M 把"。

密钥输入框旁的「显示」可核对输入；下方实时显示密钥空间大小（基础模式：单把空间；高级模式：`N/10 把密钥 · 组合空间`。绿色 = 万亿级达标，黄色 = 建议加强）。
